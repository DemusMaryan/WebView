## Докази Промпта 7, 03.11.2026

Глобально `limits.stored_jobs=100` рахує всі записи незалежно від стану, а `queued_jobs=10` залишається окремим pending cap. Count та INSERT виконуються атомарно під PostgreSQL advisory lock; відмова 429 має `stored_job_limit_reached`, `count`, `limit`. Відхилені та часткові uploads прибираються. При count понад cap старі задачі доступні, автоматичного видалення немає.

GET jobs тепер повертає об'єкт із items/total/page/page_size/total_pages/has_next/has_previous/stored_job_limit; типово 20, максимум 100, порядок created_at DESC, id DESC. Невідомі, повторені й невалідні параметри відхиляються. List не читає геометрію або JSONL. Frontend показує ліміт, сторінки й зрозумілу помилку та зберігає відкритий результат під час оновлення списку.

7 нових HTTP/PG тестів та 5 наявних reservation tests пройшли в одноразових схемах PostgreSQL без dispatcher/SLAM: конкурентні POST біля межі дали 202/429 і точний count=2; всі 7 станів, over-cap доступ, пагінація 27 записів (25 з однаковим timestamp), некоректні параметри та cleanup часткового upload перевірено. Усі колонки 51 робочого запису й підписи каталогів файлів незмінні; SHA-256 п'яти R5 reports та п'яти CV binaries збігаються. Нових задач у робочій БД немає, активних 0; isolated schemas видалені.
