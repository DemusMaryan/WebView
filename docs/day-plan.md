# Історичний план на чотири дні

Це початковий календарний план від 31.10.2026, збережений для історії, а не чинний перелік невиконаних робіт. Промпти 1–13 завершені у задокументованих локальних перевірках до 06.11.2026: R5 включає ізоляцію cancel/timeout, R3 — stored cap, R4 — auth/HTTPS, R6 — ETA, R7 — справжній nspawn-контейнер, R8 — admin monitoring. [Поточні вимоги](requirements.md), [фінальне приймання](final-acceptance.md), [команди запуску](../README.md). Дати таблиці нижче — план, не фактичні дати приймання.

| День | Заплановані роботи | Умова завершення |
| --- | --- | --- |
| 1 — 31 жовтня | Зараз: перевірений CV-прототип на короткій монокулярній послідовності RGB-кадрів з калібруванням, експорт і вимірювання. Пізніше, після окремого дозволу: відеофайл, контракт worker, базова PostgreSQL/БД/API та простий перегляд проміжних результатів; початкові R1–R3. | Для Промпту 2 — справжня траєкторія, розріджені точки, проміжні дані, виміряні час і швидкість, відтворюваний запуск у WSL. Для всього дня — шлях відео worker → БД/API → браузер і збереження результатів. |
| 2 — 1 листопада | Завершення користувацького сценарію: історія, нова задача, скасування, помилки й ліміти; авторизація та власність задач (R3–R4); доказ балансування (R5). | Наскрізний сценарій працює; чужі задачі захищені; дві реальні задачі паралельно виконуються на двох compute-серверах через Nginx з журналами доказу. |
| 3 — 2 листопада | HTTPS (R4), обмежена черга та приблизний ETA (R6), автоматичне розширення до 3 compute-серверів (R7), адміністративний моніторинг (R8). | Перевірені TLS, очікування та переповнення черги; третій сервер запускається автоматично, максимум дотримано; адміністратор бачить процеси й навантаження. |
| 4 — 3 листопада | Наскрізні перевірки R1–R8, виправлення, відтворюваний запуск і підготовка до захисту. | Для кожної вимоги збережений фактичний доказ; задокументовані команди, обмеження, результати перевірок і локальні коміти. |

Бюджет першої спроби Промпту 2 — 2–3 години разом із підготовкою, залежностями та збиранням; початок і витрачений час фіксуються. Якщо траєкторії й точок немає, записати конкретний блокер і спроби та переглянути графік. API й UI не можуть замінити результат заглушкою; власний SLAM не розробляється.

Працююче ядро, версії й прапорці з Промпта 2 збережені. Промпт 3 перевірив шлях відеофайл → API → PostgreSQL/dispatcher → Nginx → compute/worker → справжній native експорт, проміжні snapshots, ліміти, cancel/timeout і перезапуск. Великі матеріали, БД та build лежать у native файловій системі WSL; власні скрипти/патчі/документація — у поточному репозиторії. Докази й відкриті питання — у [backend-prototype.md](backend-prototype.md).

За підсумком реалізації базово працюють 2 незалежні native HTTP compute-сервери у WSL; максимум 3 — проєктне налаштування. Початкове питання відповідності R7 вирішене справжнім Linux-контейнером systemd-nspawn, а не третім звичайним процесом. Контейнер використовує спільний WSL kernel, не окрему ВМ. [Прийняті докази](autoscaling.md). Docker/Compose не використовуються. Публікацію на GitHub виконує користувач; агент створює лише перевірені локальні коміти.
