# MonoTrajectoryWeb

Навчальний вебпроєкт: обробка записаного монокулярного відео з поступовим показом оціненої траєкторії камери й розріджених 3D-точок. Масштаб відносний, результати мають зберігатися. Живий потік, повторна локалізація у збереженій кімнаті та щільна модель поза темою.

## Поточний стан

Промпт 1 завершено. У межах **Промпту 2** успішно зібрано й запущено `mono_tum` нативно у WSL: `freiburg1_xyz`, 798 вхідних RGB-кадрів, 38 валідних поз ключових кадрів, код завершення 0. Запуск тривав 44,03 с зі стандартним pacing; це не чистий час обчислення. Покадровий експортер ще потребує завершення та фактичної перевірки. API, UI, БД, Nginx, авторизація й масштабування не реалізуються; R1–R8 залишаються запланованими. Промпт 3 не виконується.

Docker, Docker Compose і Dockerfile у проєкті не використовуються. Майбутні PostgreSQL, Nginx, API, dispatcher та незалежні HTTP compute-сервери запускатимуться нативними сервісами/процесами.

## Поточний CV-етап

Стандартний приклад уже пройшов перевірку. Для його повторення з PowerShell у поточній робочій папці:

```powershell
wsl -d Ubuntu --exec bash scripts/cv/run-baseline.sh
```

Для підготовки такого самого середовища на іншій Ubuntu:

```powershell
wsl -d Ubuntu -u root --exec bash scripts/cv/install-deps-wsl.sh
wsl -d Ubuntu --exec bash scripts/cv/build-wsl.sh baseline
```

На вже зібраному середовищі повторне збирання залежностей не потрібне. Застосовані `orbslam3-cxx17.patch` і `orbslam3-headless.patch`; Pangolin збирається з `-include cstdint`. Власні shutdown/offline-патчі збережено окремо, але не застосовано. Бібліотеки знаходяться через локальний `LD_LIBRARY_PATH` дочірнього процесу, без глобального `ldconfig`. Геометрія калібрування TUM1 не змінюється; лише `Camera.RGB=0` відповідає BGR-декодуванню OpenCV.

Наступна робота цього самого Промпту 2 — покадровий експорт поз, tracking state і справжніх 3D-точок. Глибина й ground truth не подаються алгоритму. 38 поз ключових кадрів baseline не є кількістю валідних покадрових поз.

Великі вихідники, залежності, build і датасети розміщуються у файловій системі WSL поза OneDrive/диском C:. Поточний репозиторій залишається на місці й містить власні скрипти, невеликі патчі та документацію; за потреби Python використовується окреме venv. PostgreSQL/Nginx та вебкод зараз не встановлюються й не створюються; підтримка завантаженого відеофайла належить Промпту 3.

R7 зберігається в плані. Відповідність автоматичного розширення лише процесами на одному вузлі наведеним в умові ВМ/контейнерам залишається відкритим питанням.

## Git і дані

Дозволені тільки локальні коміти перевірених змін. Користувач підтвердив `versal217 <versaldata@gmail.com>`; перед кожним комітом автор і комітер перевіряються саме в середовищі виконання Git:

```powershell
git status --short --branch
git config --show-origin --get-regexp '^user\.(name|email)$'
git var GIT_AUTHOR_IDENT
git var GIT_COMMITTER_IDENT
```

Якщо даних немає або вказаний бот, підготовка продовжується без комітів до отримання точного імені та email користувача. Нові дані налаштовуються лише локально в репозиторії. Глобальна конфігурація та наявна історія не змінюються; бот не додається до `Co-authored-by`.

Push, Publish/Sync та запис змін через GitHub API заборонені; публікацію виконує користувач. Remote під час підготовки не додавався.

`.gitignore` виключає секрети й локальні `.env`, ключі/сертифікати, середовища, build, `node_modules`, дані БД, датасети, відео та результати запусків. `.env.example` можна відстежувати лише з безпечними заповнювачами. Lock-файли залежностей відстежуються. Малі fixtures можна додавати окремо після перевірки розміру та вмісту; автоматичного винятку для всіх файлів fixtures немає.
