# MonoTrajectoryWeb

Навчальний вебпроєкт: обробка записаного монокулярного відео з поступовим показом оціненої траєкторії камери й розріджених 3D-точок. Масштаб відносний, результати мають зберігатися. Живий потік, повторна локалізація у збереженій кімнаті та щільна модель поза темою.

## Поточний стан

31 жовтня 2026 року виконано лише підготовку за **Промптом 1**. Створено локальний Git-репозиторій із гілкою `main`, правила роботи та план. Реалізації ядра, API, UI, авторизації й масштабування немає; усі R1–R8 заплановані. Команди запуску застосунку ще немає. Промпти 2–5 не виконувалися.

Огляд виконано 31 жовтня 2026 року. Пакети не встановлювалися; ядро не завантажувалося й не збиралося.

| Засіб | Windows | Ubuntu у WSL2 |
| --- | --- | --- |
| ОС | Windows 11 Pro, 10.0.26200, x64; PowerShell 5.1 | Ubuntu 24.04.3 LTS, x86_64; запуск підтверджено |
| Git | 2.51.1.windows.1 | 2.43.0 |
| Python | 3.13.5 через `python` і `py` | 3.12.3 через `python3` |

Дистрибуції `Ubuntu` і `docker-desktop` зареєстровані як WSL2. Ubuntu була зупинена до перевірки й успішно запустилася для огляду. Компіляцію C++ та сумісність стеку з ядром ще не перевіряли.

Повторити основні перевірки з PowerShell:

```powershell
git --version
python --version
node --version
npm --version
wsl --list --verbose
wsl -d Ubuntu -- cat /etc/os-release
wsl -d Ubuntu -- python3 --version
wsl -d Ubuntu -- cmake --version
wsl -d Ubuntu -- g++ --version
docker --version
docker compose version
docker info
```

## Що потрібно перед CV-прототипом

На наступному окремо дозволеному етапі потрібно перевірити шлях збирання ORB-SLAM3 у доступному WSL/Linux, зафіксувати версії та встановити лише необхідні залежності. Потрібні перевірена коротка монокулярна послідовність і відповідне калібрування; зараз їх у проєкті немає. Наявність CMake/g++ сама по собі не доводить готовність ядра.

Для шляху через Docker потрібно забезпечити доступний Docker Engine та інтеграцію з обраним середовищем. Наразі контейнерний запуск заблокований; запуск CV без Docker ще не перевірявся. Linux Node знадобиться, якщо frontend надалі збиратиметься всередині WSL; Windows Node/npm уже доступні.

## Git і дані

Дозволені тільки локальні коміти з налаштованою ідентичністю користувача. Перед кожним комітом перевіряються автор і комітер:

```powershell
git status --short --branch
git config --show-origin --get-regexp '^user\.(name|email)$'
git var GIT_AUTHOR_IDENT
git var GIT_COMMITTER_IDENT
```

Якщо даних немає або вказаний бот, підготовка продовжується без комітів до отримання точного імені та email користувача. Нові дані налаштовуються лише локально в репозиторії. Глобальна конфігурація та наявна історія не змінюються; бот не додається до `Co-authored-by`.

Push, Publish/Sync та запис змін через GitHub API заборонені; публікацію виконує користувач. Remote під час підготовки не додавався.

`.gitignore` виключає секрети й локальні `.env`, ключі/сертифікати, середовища, build, `node_modules`, дані БД, датасети, відео та результати запусків. `.env.example` можна відстежувати лише з безпечними заповнювачами. Lock-файли залежностей відстежуються. Малі fixtures можна додавати окремо після перевірки розміру та вмісту; автоматичного винятку для всіх файлів fixtures немає.
